# 中文说明文档

这份文档是给项目组内部使用的中文说明，目的是帮助大家快速理解 `Final version` 文件夹里每个文件的作用、正确运行顺序，以及这套新版实验方案和之前版本相比到底改了什么。

## 一、为什么要重做这一版

之前版本的核心问题是：

- 很多特征是在全量数据上先算好的
- 然后才做 `GroupKFold`
- 这样会导致信息泄漏

特别是下面这些特征，如果先在全量数据上拟合，再拿去做交叉验证，就不严格：

- KMeans 用户分群
- Apriori 规则
- ALS 特征
- `cluster_product_target_rate`

因此这次重做的核心目标是：

1. 保留原项目在 `final.md` 中已经确定的任务定义
2. 把所有会“学习数据结构”的步骤改成只在 `train` 上拟合
3. 保证最后的主结果、消融实验、分层分析方法上是严谨的

## 二、这次的任务定义是什么

这次的数据定义严格按照项目原本 final 报告的逻辑来做。

### 1. 原 Kaggle 的 `train/test` 不是我们最终监督学习里的 train/test

原始 Instacart 数据集是一个比赛数据集：

- `eval_set = train` 的用户，最后一个订单有商品标签
- `eval_set = test` 的用户，最后一个订单没有商品标签

如果直接沿用 Kaggle 的 train/test，不适合我们现在的监督学习建模。

### 2. 我们的重构方式

对于每个用户，都重新定义：

- `target order`：该用户最后一个**有 product-level 信息**的订单
- `history orders`：该 target 之前的所有订单

具体是：

- 对原 `train` 用户：
  - `target = train order`
- 对原 `test` 用户：
  - `target = 最后一个 prior order`

然后统一做成监督学习问题：

- 候选单位：`(user, product)`
- `label = 1`：该商品出现在 target order 中
- `label = 0`：该商品不在 target order 中

### 3. Candidate generation

候选商品只从该用户的 `history` 中来，也就是：

- 只保留用户之前买过的商品作为候选

这样既符合 grocery reorder prediction 的业务场景，也能控制候选空间大小。

## 五、为什么这次方法更严谨

这次最重要的改动是：

### 1. 全局安全的部分和 train-only 学习的部分分开了

预处理脚本只输出：

- 订单表
- history 明细
- target 明细
- labels
- candidates
- 商品元数据

这些是可以安全提前保存的。

### 2. 所有会学习结构的特征都改成只在 `train` 上学习

在 notebook 里，真正拟合时只用 `train users` 做：

- user/product/user-product 聚合
- KMeans
- `cluster_product_target_rate`
- Apriori
- ALS

然后再把 `train` 学到的对象应用到 `validation` 和 `test`。

这样就避免了：

- 测试用户信息提前进入特征
- 测试标签统计被提前用掉

## 六、现在的实验设计是怎么定的

这部分是根据你最后拍板的方案定下来的。

### 1. 主实验

主实验只在：

- `with_als`

这个最终 feature set 上做正式调参。

调参方式是：

- 固定的 `train / validation / test` 三段式
- 按 `user_id` 做一次性划分
- 调参目标：`AUC`

也就是说：

- `train`：拟合所有特征工程对象和模型
- `validation`：调参、选模型、开发期检查
- `test`：最终泛化评估

### 2. 消融实验

消融实验不再每个 stage 单独重新调参，也不再把 `validation` 当成最终展示结果。

而是：

- 先用主实验拿到一套固定参数
- 再用这套参数做逐步加特征的消融
- 最终报告和画图时主看 `test`

特征阶段是：

1. `interaction_only`
2. `+ user/product`
3. `+ kmeans`
4. `+ apriori`
5. `+ als`

这里 `ALS` 不再被特殊对待，而是和其他特征组一样，只是最后一层 feature block。

### 3. 分层分析和 top-k 分析

这两个分析都基于主实验得到的预测结果来做：

- segment analysis：按 `user_cluster`
- top-k strategy analysis：比较固定 `k=11` 和动态 `k`

其中：

- 分层分析最终展示主看 `test`
- top-k 也可以优先汇报 `test`
- `validation` 结果保留用于内部开发参考

### 4. KMeans 和 Apriori 的专门输出

因为 `KMeans` 和 `Apriori` 是你们方法里比较重要的组成部分，所以 notebook 里额外保留了它们各自的诊断输出。

`KMeans` 现在会输出：

- `kmeans_cluster_profile.csv`
- `kmeans_diagnostics.png`

这里会展示：

- 每个 cluster 的用户数量
- 每个 cluster 在 `u_total_orders`、`u_avg_days_between_orders`、`u_avg_basket_size`、`u_reorder_ratio`、`u_unique_products` 上的均值画像

`Apriori` 现在会输出：

- `apriori_top_rules.csv`
- `apriori_rules.png`

这里会展示：

- support / confidence / lift 过滤后的 top rules
- 代表性 aisle 规则在 `lift` 和 `confidence` 上的强度
